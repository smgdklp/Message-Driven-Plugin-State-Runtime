# mdpsr 插件规范（ABI v3）


---

## 一、最小插件

### 1.1 住在哪、怎么编

| 种类 | 住在哪 |
| --- | --- |
| **组件** | `src/components/<名字>/` |
| **测试夹具** | `test/<名字>/`（刻意不进 `src`：删掉整个目录，框架一样跑） |

两边都是**各自独立的 CMake 工程** —— 每个文件夹自带 `CMakeLists.txt` + `plugin.json`，
产物进 `<BUILD>/plugins/<名字>/`（`<BUILD>` 就是根 CMakeLists 的 `BUILD` 开关，
默认 `<根>/build`），可以整个目录拷走。

> **`sysmgr` 是例外**：它是**内核组件**，住在 `src/main/sysmgr/`，由框架的
> `CMakeLists.txt` 和框架**一起编译**，**不进 `PLUGIN_LIST`**。别拿它当插件模板 ——
> 写新插件请照抄 `src/components/alpha/`（最简）或 `src/components/paint/`（GUI 客户端）。

新增一个组件的完整流程：

1. 在 `src/components/` 下建文件夹，放 `plugin.json` + `.cpp` + `CMakeLists.txt`
   （顺手放一份短 `README.md`："这是什么 / 有哪些条目 / 看日志找什么"）。
2. 让它被编出来 —— 二选一：
   * 点名：`-DPLUGIN_LIST="src/components/hello"`
   * 或走 `Mode`：`-DMode=TXST2` 会把 `src/components/` 下**所有**文件夹都编一遍
3. 加进 `src/main/config.json` 的基准清单（它决定**加载顺序**）。
   产物里的 `<BUILD>/config.json` 是根 CMakeLists 按"基准清单 ∩ 本次编出来的集合"
   生成的，不用手改。

根 CMakeLists 的完整用法（`BUILD` / `PLUGIN_LIST` / `Mode` 三个开关）见
[../README.md](../README.md) 的"怎么编译"，设计理由见 [架构.md](架构.md) 第一节。

### 1.2 三个文件

三个文件：`plugin.json` + 一个 `.cpp` + `CMakeLists.txt`。

**plugin.json**

```jsonc
{
  "name":     "hello",                  // 全局唯一
  "dll_path": "mdpsr_hello.dll",        // 相对本清单所在目录 (可以是数组)
  "State":    ["hello.Count"],          // -> mdpsr_state_hello_Count
  "Handle":   ["hello.Handle"],         // -> mdpsr_handle_hello_Handle
  "Init":     "hello.Handle"            // 可选: 谁的 cmd=0 是初始化入口
}
```

**hello.cpp**

```cpp
#include "mdpsr/abi.h"
#include <cstring>

#define HELLO_COUNT_MAGIC 0x48454c31u   /* "HEL1" */
typedef struct hello_count { uint32_t magic; uint32_t n; } hello_count;

#define HELLO_CMD_BUMP (MDPSR_CMD_USER_BASE + 0)   /* 插件命令从 16 开始 */

/* State 工厂: 从 ctx->pool 分配, 返回载荷指针 */
MDPSR_EXPORT void* mdpsr_state_hello_Count(const mdpsr_factory_ctx* ctx) {
    if (!ctx || !ctx->pool) return NULL;
    void* mem = mdpsr_fctx_alloc(ctx, sizeof(hello_count), alignof(hello_count));
    if (!mem) return NULL;
    hello_count* c = (hello_count*)mem;
    c->magic = HELLO_COUNT_MAGIC;
    c->n = 0;
    return c;
}

/* Handle: 无状态入口 */
MDPSR_EXPORT int mdpsr_handle_hello_Handle(const mdpsr_msg* msg, const uint8_t* body,
                                           uint32_t len, const mdpsr_ctx* ctx) {
    if (!msg || !ctx || !ctx->host) return MDPSR_ERR_NULLPTR;
    const mdpsr_host* H = ctx->host;

    if (msg->cmd == MDPSR_CMD_INIT) {
        mdpsr_log(H, 0, "[hello] cmd=0 初始化");
        return MDPSR_OK;
    }
    if (msg->cmd != HELLO_CMD_BUMP) return MDPSR_ERR_UNKNOWN_CMD;

    /* 借自己的 State —— 借到就持锁, 用完必须还 (或交给宿主兜底) */
    void* p = NULL; uint32_t gen = 0;
    const int rc = mdpsr_acquire(H, mdpsr_hash64("hello.Count"), 0, &p, &gen);
    if (rc != MDPSR_OK) return rc;                  /* 资源没了就是没了, 别解引用 */
    hello_count* c = (hello_count*)p;
    if (c->magic == HELLO_COUNT_MAGIC) c->n++;
    const uint32_t n = c->n;
    mdpsr_release(H, mdpsr_hash64("hello.Count"));

    mdpsr_reply rep = {0};
    rep.cmd = HELLO_CMD_BUMP; rep.code = 0; rep.src = ctx->handle; rep.value = n;
    return mdpsr_send_reply(H, msg, MDPSR_CMD_REPLY, &rep, sizeof(rep));
}

MDPSR_DECL_ABI_VERSION()                       /* 导出 mdpsr_abi_version */

MDPSR_EXPORT int mdpsr_module_init(const mdpsr_factory_ctx* ctx) {
    (void)ctx; return MDPSR_OK;                /* 可选, 但一般都写 */
}
MDPSR_EXPORT void mdpsr_module_fini(void) {}   /* 可选 */
```

被编出来（进 `PLUGIN_LIST` 或落在 `Mode` 覆盖的范围里）**并且**出现在基准清单
`src/main/config.json` 里，就会进产物那份生成的 `<BUILD>/config.json`，启动时就装上了。

## 二、清单字段

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `name` | ✔ | 插件名，全局唯一，≤ 63 字节 |
| `dll_path` | ✔ | 相对**本清单所在目录**；字符串或字符串数组 |
| `Handle` | ✔ | 至少一个；导出 `mdpsr_handle_<条目名>` |
| `State` | | 导出 `mdpsr_state_<条目名>`，可选 `..._destroy` |
| `Object` | | 导出 `mdpsr_object_<条目名>`，可选 `..._destroy` |
| `Queue` | | 要用的队列名；写三条固定队列的名字表示"我要用那一条" |
| `Init` | | 谁的 `cmd=0` 是初始化入口；必须在 `Handle` 里声明过 |
| `kernel` | | `true` 才有装卸别的插件的权限（默认 false） |
| `list` | | 给工厂的附加字符串数组，工厂里从 `ctx->list / ctx->list_count` 取 |

**条目名 → 导出符号**：非 `[A-Za-z0-9_]` 的字符统一变成 `_`。
`hello.Count` → `mdpsr_state_hello_Count`。

⚠ 三条硬规则（装载时会真的检查，违反就装不上）：

1. 条目名在**全进程**唯一（两个插件不能都叫 `Config`）；
2. 同一个清单里不能重名；
3. 两个不同的条目名**去符号之后不能撞**（`A.B` 和 `A_B` 会推出同一个符号 → 拒绝）。

## 三、四类导出

### State —— 公用数据对象

```c
void* mdpsr_state_<名>(const mdpsr_factory_ctx* ctx);
void  mdpsr_state_<名>_destroy(void* instance, const mdpsr_factory_ctx* ctx);  // 可选
```

* 从 `ctx->pool`（= 本插件的池）分配，返回**载荷指针**。
* 约定放**纯数值/公开数据**；跨插件共享的就是它。
* 建议载荷头 4 字节放一个 `magic`，接手的人用来确认"这确实是我认识的那个结构"
  （自测里就是这么做的）。

### Object —— 私有类实例

```c
void* mdpsr_object_<名>(const mdpsr_factory_ctx* ctx);
void  mdpsr_object_<名>_destroy(void* instance, const mdpsr_factory_ctx* ctx);  // 可选
```

* 也是从 `ctx->pool` 分配。
* **别人借不到**：`acquire` 一个属于别的插件的 Object 会返回 `NO_PERM`
  （State 才是公用的）。
* `_destroy` 里**只做析构**（`p->~T()`），不要自己 `free` —— 内存由池整池回收。
  想在对象的一生里提前还，可以 `mdpsr_fctx_free`。

### Handle —— 无状态消息入口

```c
int mdpsr_handle_<名>(const mdpsr_msg* msg, const uint8_t* body,
                      uint32_t body_len, const mdpsr_ctx* ctx);
```

三条纪律：

1. **判命令只读 `msg->cmd`**；body 里的参数"长度够才读"。
   宿主点火用的是 4 字节的短消息，先要求整条结构体再判断会让组件直接变砖。
2. **不要保存指针**跨消息使用。要用就 `acquire`，用完 `release`。
3. **不要长时间阻塞**（sleep、等 IO）。你占着 handle 锁，卸载会在 `join` 那里等你。

返回 `MDPSR_OK` 表示成功；返回 `MDPSR_ERR_BUSY` 会被宿主当成"我很忙"，消息**回滚重投**；
其它非 0 值记一条 WARN 并按失败处理。

### Queue —— 队列工厂

```c
int mdpsr_queue_<名>(const mdpsr_factory_ctx* ctx, mdpsr_queue_desc* out);
```

只回答"这条队列要什么参数"：`capacity`（字节硬上限）和 `pace_ms`。
**在清单里声明 `Queue`** 才会被调用；声明了但导出找不到，就退回默认参数。
插件也可以运行时自己建队列：`host->queue_create(name, &desc, &key)`
（会被记在本插件名下，卸载时一起收掉）。

⚠ 队列的归属是**硬边界**：

* 运行时 `queue_create` 对同一个名字只在**同一个主人**那里是幂等的；名字已经被别人
  的插件占了 → `ALREADY_EXISTS`（不会把别人的队列登记成自己的，否则卸载时会把别人的
  队列线程一起拆掉）。
* `queue_bind(handle, queue)` 只接受"自己的 handle + 自己的（或宿主的）队列"，
  否则 `NO_PERM`。把消息改道到别人的队列上跑 = 让别人替你背卸载时的 join。

## 四、借资源：唯一允许的用法

```c
void* p = NULL; uint32_t gen = 0;
int rc = mdpsr_acquire(H, key, 0, &p, &gen);     // 0 = "哪一代都行"
if (rc != MDPSR_OK) return rc;                    // 拿不到就返回, 绝不解引用
... 用 p ...
mdpsr_release(H, key);                            // 或者 mdpsr_release_all(H)
```

一次要借多个，**用 `mdpsr_acquire_many`**（宿主内部按键升序借，全有或全无）：

```c
uint64_t keys[2] = { mdpsr_hash64("a.State"), mdpsr_hash64("a.Obj") };
void*    ptrs[2] = { NULL, NULL };
uint32_t gens[2] = { 0, 0 };
int rc = mdpsr_acquire_many(H, keys, NULL, 2, ptrs, gens);
...
mdpsr_release_all(H);
```

### 三条规则

1. **同一个线程里，后借的键必须比手上所有键都大**，否则 `LOCK_ORDER`。
   这条规则换来的是"插件之间互相咬锁"不可能发生。写代码时按名字排序借即可，
   或者干脆用 `acquire_many`。
2. **不要借自己已经拿着的东西**：会返回 `BUSY`（v1 那里是自锁死）。
3. **不要跨调用持有**：宿主在每次调用结束时兜底归还。真漏了会记 WARN
   （`兜底还锁`），不会把系统卡死，但那是 bug。

### `gen` 怎么用

* 只是"现在要用一下当前这一代" → `want_gen` 传 `0`。
* 存过 `(key, gen)` 想确认"还是不是当初那个" → 传存下来的 `gen`，
  换过代会得到 `STALE`（比如你缓存了别人的 State，结果人家重载了）。

`mdpsr_gen_of(H, key)` 是无锁快照：返回 0 = 不存在或已失效。
"对方在不在"就用它，不要用 `acquire` 去试探。

### 上线门闸：为什么偶尔会看到 `NOT_READY`（11019）

一个插件**装到一半**的时候，它的条目已经挂进表了（`gen` 也有值），但**谁也借不到** ——
`acquire` 会返回 `NOT_READY`，`gen_of` 会返回 0。要等它整个装好、"上线"那一刻才可借。

* 你**不需要**为它写特殊逻辑：分发路径已经替你挡住了 —— 投给一个还没上线的 handle 的
  消息会被**回滚重投**，等它上线下一轮再跑，不是死信。
* 只有"你自己主动去借一个正在被装载的插件的东西"时才会看到这个码：当下最正确的反应是
  下轮再来（`BUSY` 的那种处理方式）。
* 反过来，**卸载**中的资源是 `ENTRY_INVALID`（12002）/ `STALE`（11015）—— 那是真的走了。

## 五、消息与协议

### 帧头（宿主填，插件只读）

```c
typedef struct mdpsr_msg {
    uint64_t dst;    // 我 (收到消息时)
    uint64_t src;    // 发件人, 0 = 宿主
    int32_t  cmd;
    int32_t  len;    // 整帧字节数
} mdpsr_msg;
```

### 保留命令（插件应该礼貌处理，别回 `UNKNOWN_CMD`）

| cmd | 名字 | 含义 |
| --- | --- | --- |
| 0 | `MDPSR_CMD_INIT` | 初始化（≈ main）。**会收到 4 字节的短消息** |
| 1 | `MDPSR_CMD_REPLY` | 通用成功回复（载荷 `mdpsr_reply`） |
| 2 | `MDPSR_CMD_FAIL` | 通用失败回复（载荷 `mdpsr_fail`）："你有条消息没送到" |
| 3 | `MDPSR_CMD_PING` | 收到请回 `PONG` |
| 4 | `MDPSR_CMD_PONG` | 对 `PING` 的回复 |
| 5 | `MDPSR_CMD_STOP` | 请停下自转循环 |
| **16+** | 插件自己的命令 | 各插件自己定义 |

### 投递与回复

```c
mdpsr_emit(H, dst, cmd, body, len);            // src = 我自己 (当前 handle)
mdpsr_emit_from(H, dst, src, cmd, body, len);  // 指定 src
mdpsr_emit_to(H, queue_key, dst, src, cmd, body, len);   // 指定队列
mdpsr_send_reply(H, msg, cmd, body, len);      // 回给 msg->src (src=0 就什么都不做)
```

* **跨插件唯一允许的通信方式**。你不需要知道对方是谁、用什么语言写的。
* 想让对方回你，投消息时 `src` 必须非 0（用 `emit_from`，或让 `emit` 用你自己的 handle）。
* `mdpsr_emit*` 会返回 `MDPSR_ERR_QUEUE_FULL`：对方队列满了。
  **这是正常反馈，不是错误** —— 退让一下再投，或者记 INFO 就行。

## 六、线程模型

| 线程 | 跑什么 |
| --- | --- |
| 宿主主线程 | **什么都不跑**（只 `init`/`boot` 然后等退出）。它不分发消息、也不泵 Win32 |
| `Queue_sys` 线程 | 内核组件（`sysmgr`）的 handle |
| `Queue_default` 线程 | 所有没声明队列的 handle |
| 每条自申请队列 | 声明绑上去的 handle |
| 插件自己 `std::thread` | **框架不管**（`winmsg` 的 GUI 线程就是这种）；卸载前自己 join |

**同一条队列上的消息天然串行**（一个 dispatcher 一次处理一条）。
把"收事件的 handle"和"刷新的 handle"声明成**同一条队列**，就白拿一层串行 ——
`paint` 就是这么干的：它内部一行锁都不用写。

⚠ **初始化的线程契约**：装载时宿主默认在**调用者线程**上同步跑一次 `cmd=0`
（`MDPSR_INSTALL_SYNC_INIT`）。所以 `cmd=0` 里**不要假设自己在自己的队列线程上**：

```cpp
/* 反例: 在 cmd=0 里做需要线程亲和的活 (建窗口、绑线程局部存储) */
/* 正例: cmd=0 只登记, 把真正的活投给自己, 让它回到自己的队列上做 */
case MDPSR_CMD_INIT: {
    ... 记账 ...
    return mdpsr_emit(H, ctx->handle, MY_CMD_START, NULL, 0);   /* 回到自己的队列 */
}
```

（`winmsg` 是唯一的例外，而且是"合法的例外"：它的 `cmd=0` 只做一件事 ——
**起一条新线程**。新线程从第一行起就在它自己身上，所以窗口的线程亲和没问题。）

⚠ **自己开的线程，卸载前自己 join。** 框架只 join 它自己建的队列线程。
Object 的 `_destroy` 里 signal + join 是唯一正确的收尾位置（`_destroy` 一定在
`FreeLibrary` 之前、而且那时池和 Object 都还活着）。

⚠ **内核插件（`"kernel": true`）调用装卸时，必须自己处理 `BUSY`。**
宿主对"插件代码发起的装卸"用**不阻塞**的策略：拿不到管理面就返回 `BUSY`（11011），
而不是等 —— 因为卸载路径持着管理面的锁去 join 队列线程，插件代码要是也阻塞在那把锁上
就是一个死环（见 [架构.md](架构.md) 第四、九节）。所以：

```c
int rc;
for (int i = 0; i < 200; ++i) {
    rc = H->plugin_uninstall(H->self, target, 0);   /* 或 install/reload */
    if (rc != MDPSR_ERR_BUSY) break;
    H->sleep_ms(H->self, 1);                        /* 下轮再来 */
}
```
（`sysmgr` 就是这么写的：`call_mgmt()`。）

## 七、GUI：怎么让插件显示东西（不用碰 Win32）

框架自带 `winmsg` 组件：它是 GUI broker，你的插件**一行 Windows 代码都不用写**。
完整例子见 `src/components/paint/paint.cpp`（那个文件里没有 `windows.h`）。
**完整说明见 [GUI.md](GUI.md)** —— 这里只留最少够用的那点。

### 7.1 你要做的四件事

```
① 清单里声明一个 State:   "State": ["<插件名>.Surface"]     ← 名字必须正好是这个
   工厂里:                return winmsg_surface_make(ctx, 图宽, 图高);
                          (图像内存从 ctx->pool 出, 卸载时随池一起回收)

② 要一个窗口 + 订阅事件:  winmsg_open_ex(H, 窗口名, x, y, 宽, 高,
                                       收事件的handle, 事件位掩码, 可否整窗拖动,
                                       &surface_key);
   等状态变 READY:        while (winmsg_state(H, 窗口名) != WINMSG_S_READY) 等一会;
   窗口没了就再要一个:     if (winmsg_state(H, 窗口名) == 0) 再调一次 winmsg_open_ex(...);
                          ← 名字就是句柄, 不用改名; ★ 订阅必须跟着一起重新声明

③ 每一帧:               winmsg_surface* s = NULL;
                          if (winmsg_lock_ex(H, surface_key, &s) == MDPSR_OK) {
                              ... 改 s->pixels / scale_x / scale_y / img_pos ...
                              winmsg_unlock(H, surface_key, s, /*changed=*/1);
                          }
                          ← 返回 BUSY 是"忙", 下轮再来; 别把自转链掐断

④ 收事件 (自己的队列线程上, cmd = WINMSG_CMD_EVENT):
                          winmsg_event ev;
                          if (mdpsr_read(body, len, &ev, sizeof(ev))) { switch (ev.kind) ... }
```

需要的头文件（**都不含 Windows 头**）：

```c
#include "winmsg_protocol.h"   /* 协议: 结构体 / 常量 / 事件种类 */
#include "winmsg_client.h"     /* 助手: open/subscribe/state/lock/unlock/... */
```

**两个几何参数**（GUI 里最常动的就是这两个，坐标系原点统一在**左上角**，和 Win32 一致）：

| | 管什么 | 怎么改 |
| --- | --- | --- |
| **RECT**（`slot.win`） | 窗口在屏幕上的**绝对位置与尺寸** | `winmsg_move` / `winmsg_resize` / `winmsg_set_rect` / `winmsg_get_rect` |
| **POINT + 缩放**（`surf.img_pos` / `surf.scale_*`） | **图在窗口里怎么摆**：先按 scale 缩放（0 = 1.0，负 = 镜像），再把**原图左上角**放到 `img_pos` | `winmsg_set_offset`（= `winmsg_place_image`）/ `winmsg_set_scale`，或锁里直接改 |

**内存图像是 4 通道 BGRA**：每像素 4 字节、内存里 `B,G,R,A`（当 `uint32_t` 读是
`0xAARRGGBB`）、行序自上而下、给"直通" alpha 不用预乘、**`A=0` 的地方真的透明**
（`alpha=0` 的地方透出桌面）。窗口本身就是裁剪区：图超出客户区的部分**根本不写**，
没盖到的地方就是透明的（窗口是 `WS_EX_LAYERED` 分层窗口，默认纯透明）。
`winmsg_draw_circle(s, 0xFFRRGGBB)` 是最省事的演示画法（透明底 + 一个纯色圆）。

**整窗可拖是可选的**：`WINMSG_F_DRAGGABLE` 给了就"按住窗口任意位置能拖"，代价是
那扇窗收不到真实的鼠标按下/抬起（系统拿去跑拖拽了）。默认不开 = 普通客户区，
点击/抬起/滚轮/按键都真的到客户端。

### 7.2 三条通道，别用错

| 你想干的事 | 用哪个 | 为什么 |
| --- | --- | --- |
| 改画面（换图/缩放/偏置） | `winmsg_lock_ex` → 改 → `winmsg_unlock(changed=1)` | 只有"最新一版"有意义；**内容没变就别调**（changed=0 不会触发重绘） |
| 挪窗口 / 改窗口大小 | `winmsg_move` / `winmsg_resize`（RECT + `win_seq`） | broker 下一帧 `SetWindowPos`，并把系统认的实际矩形写回 `slot.cur` |
| 知道"用户按了什么" | 事件消息（`cmd=16`） | 每条都不能丢；处理慢也只卡你自己的队列线程 |
| 知道"鼠标在哪、哪个键按着" | `winmsg_read_input()` 轮询 | 一秒上百条，走消息会把你自己的队列灌满 |
| 知道"窗口真的显示出来了吗" | `winmsg_is_visible()` | broker 从系统读的 `IsWindowVisible`；`state==READY` 只说明目录登记好了 |

**画面是"最新值"语义**：你来不及画的那几版会被自然合并掉。别指望"每一版都显示过"。

### 7.3 硬规则（违反会崩或者不刷新）

* **`pixels` 只在 `winmsg_lock_ex` 和 `winmsg_unlock` 之间有效。**
  那把锁同时是"我正在用它"的声明 —— broker 贴图时也 `acquire` 它，所以客户端
  卸载会被推迟而不是留下悬垂指针。绕过锁直接读 `pixels` = 拿悬垂指针。
* **换图像指针 / 释放旧图**，都必须在 `winmsg_lock_ex` 期间做。
* 客户端内部调用顺序：**先读状态（`winmsg_state`/`winmsg_read_input`）→ 再 `winmsg_lock_ex`**。
* 图省事就在**一条队列**上收事件 + 刷新（`paint` 就是这样），这样两边天然串行，
  你一行锁都不用写。
* **窗口被回收之后重新登记，订阅要一起重新声明** —— 用 `winmsg_open_ex`（一步到位）。
  格子是跟着窗口一起回收的：只 `winmsg_open` 的话新窗口"没有订阅"，事件会静静地消失。
* `winmsg_lock_ex` 返回 `BUSY` 是正常回退（资源正被 broker 借走），下轮再来就行 ——
  别像"资源没了"那样把自己的自转链掐断。
* 窗口是**无边框、默认全透明、只画一张图**。标题栏/按钮/输入法都没有 —— 要就自己画在
  画面里；要"按住能拖"就点名 `WINMSG_F_DRAGGABLE`。

### 7.4 事件种类

| `kind` | 什么时候来 | `code` / `x,y` |
| --- | --- | --- |
| `WINMSG_EV_READY` | 窗口建好了（发一次） | — |
| `WINMSG_EV_CLOSE` | 用户要关（Alt+F4） | — |
| `WINMSG_EV_DESTROYED` | 窗口已销毁（最后一次） | — |
| `WINMSG_EV_KEY_DOWN/UP` | 键盘 | `code` = 虚拟键码；`mods` 带 Shift/Ctrl/Alt |
| `WINMSG_EV_CHAR` | 字符输入 | `code` = 字符码 |
| `WINMSG_EV_MOUSE_DOWN/UP` | 鼠标键 | `code` = 按钮位；`x,y` = 客户区坐标 |
| `WINMSG_EV_WHEEL` | 滚轮 | `code` = 有符号增量（一格 = 120） |
| `WINMSG_EV_FOCUS_IN/OUT` | 获得/失去焦点 | — |
| `WINMSG_EV_MOUSE_MOVE` | **默认不发**，只有你在 `events` 里点名才发 | `x,y` |

想收哪些就在 `winmsg_subscribe` 的掩码里点名（`WINMSG_EV_BIT(kind)`）。
**`events = 0` 或 `handle = 0` = 一条消息都不发**，纯"给我个显示面板"。

窗口被关掉（用户关的、或者 broker 回收的）**不走消息也能知道**：
`winmsg_state()` 返回 `0` 就是"没这个窗口了"。

## 九、发版前的自检清单

- [ ] `mdpsr_abi_version` / `mdpsr_module_init` 导出了吗？
- [ ] 清单里的条目名和 `plugin.json` **逐字一致**吗？（改一个字符键就变了）
- [ ] 每个条目的导出符号按规则拼对了吗？（`A.B` → `A_B`）
- [ ] 工厂是不是都用 `ctx->pool` 分配？有没有混用 `new` / `malloc`？
- [ ] `acquire` 之后所有分支都 `release` 了吗？（包括提前 `return` 的分支）
- [ ] **同一个调用里有没有嵌套借两个资源？**（键的哈希大小是任意的，嵌套借必然
      有一半概率违反"按键升序"→ `LOCK_ORDER`。要借多个请用 `acquire_many`）
- [ ] `cmd` 判断是不是只读 `msg->cmd`？body 参数是不是"长度够才读"？
- [ ] `MDPSR_CMD_FAIL` / `PONG` 这些保留命令会不会被你回 `UNKNOWN_CMD`？
- [ ] `cmd=0` 里有没有假设"我在自己的队列线程上"？
- [ ] **自己开的线程，卸载前 join 了吗？**（框架不管它 —— 忘了就是卸载时崩）
- [ ] 自转循环有没有**终止条件**？（限速是保险，不是许可）
- [ ] `mdpsr_emit` 的 `QUEUE_FULL` 处理了吗？
- [ ] GUI 客户端：`pixels` 是不是只在 `lock_ex`/`unlock` 之间用？
- [ ] GUI 客户端：窗口被回收后**重新登记时订阅也重新声明**了吗？（用 `winmsg_open_ex`）
- [ ] GUI 客户端：`winmsg_lock_ex` 的 `BUSY` 会不会把自转链掐断？（不该）
- [ ] 内核插件：`plugin_install/uninstall/reload` 的 `BUSY` 重试了吗？
- [ ] `_destroy` 里只做析构、没有自己 `free` 吧？
- [ ] 跑一遍 `build\mdpsr.exe --selftest --cycles 1000`，看日志里有没有你的 WARN？
      （注意 `--selftest` 会跑 GUI 阶段，需要把 `test/` 里的 `circ_a`/`circ_b`/`circ_c`
      也编出来 —— 用 `TXST2` 只编组件是跑不完整的）
- [ ] 改了 GUI 相关的东西？再跑一遍 `build\mdpsr.exe --guitest`（几秒钟，122 条断言）。
      这条用 `-DMode=TXST1` 那个场景，产出目录 `build_TXST1\`。
