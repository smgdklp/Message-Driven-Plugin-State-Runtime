## 零、十秒速览

一个插件 = **一个 dll + 一份 `plugin.json`**。你要写的只有四类导出函数：

| 种类 | 导出名 | 干什么 |
| --- | --- | --- |
| Handle | `mdpsr_handle_<条目名>` | **无状态**消息入口（必须至少一个） |
| State | `mdpsr_state_<条目名>` | 造一个**公用数据对象**，从 `ctx->pool` 分配 |
| Object | `mdpsr_object_<条目名>` (+ `_destroy`) | 造一个类实例，从 `ctx->pool` 分配 |
| Queue | `mdpsr_queue_<条目名>` | 回答"我要的队列要什么参数"（可选） |

外加三个模块级导出：

```cpp
MDPSR_EXPORT uint32_t mdpsr_abi_version(void);                          // 必须
MDPSR_EXPORT int      mdpsr_module_init(const mdpsr_host*, uint64_t);   // 必须
MDPSR_EXPORT void     mdpsr_module_fini(uint64_t);                      // 可选
```

**先读第一节的硬性要求。** 那 12 条是"错了就会崩 / 会静默失效"的，其余都是解释。

---

## 一、硬性要求（写之前先看这张表）

| # | 要求 | 违反了会怎样 |
| --- | --- | --- |
| 1 | **Handle 必须无状态**：不持有、不修改任何可变全局量 | 多线程下数据竞争；卸载后悬垂 |
| 2 | **载荷判分只读前 4 字节 `_cmd`**，参数在长度够的时候再读 | 收到短消息直接变砖（宿主点火只给 16 字节） |
| 3 | **长度一定要校验**，绝不解引用越界数据 | 越界读 / 崩溃 |
| 4 | **工厂必须用 `ctx->pool` 分配**，不要 `new` / `malloc` | 卸载时收不回来，内存漏 |
| 5 | **Object 析构必须还回同一个池**（先取池 → 析构 → deallocate） | **堆损坏**（退出码 `0xC0000374`） |
| 6 | **异常不许穿过 dll 边界**，工厂和 handle 内部自己 `try/catch` | 未定义行为，通常直接崩 |
| 7 | **条目名全局唯一**（handle 与 object 不能同名；队列名也共用同一个键空间） | 注册失败 `11010`，组件少一块 |
| 8 | **条目名里非 `[A-Za-z0-9_]` 的字符在符号里会变成 `_`**，规范化后必须仍唯一 | 静默命中另一个同名符号 |
| 9 | **要循环就"把消息回滚给自己"**，不要 `while(1)`、不要 `sleep` | 占死队列线程 / 空转烧 CPU |
| 10 | **不许在自己的队列线程上卸载自己** | `plugin_unload` 会 join 自己 → 死锁 |
| 11 | **只能碰 `Context` 里给出来的东西**，不要去摸别的组件的类实例 | 违反隔离；对方卸载后悬垂 |
| 12 | **跨 dll 的载荷用 POD / 显式序列化**，别塞 `std::string`、指针、虚表 | 布局不一致，静默错乱 |

## 二、身份：一切都是"名称哈希"

### 2.1 规则

```c
uint64_t key = mdpsr_hash64("Ticker.Handle.Tick");
```

* 这个 `uint64_t` 就是物体在全进程的唯一标识，也是 `MainMap` 的**唯一键空间**。
* **组件之间不需要 include 对方的头文件** —— 只要名字对上就能互相找到。
* 名字可以是任意 UTF-8 字符串（`Ticker.Handle.Tick` 完全可以）。

### 2.2 条目名 → 导出符号

条目名是给人看的，导出符号名由它推出来：**非 `[A-Za-z0-9_]` 的字符统一变成 `_`**。

| 条目名 | 导出符号 |
| --- | --- |
| `Ticker.Ticks` | `mdpsr_state_Ticker_Ticks` |
| `Ticker.Keeper` | `mdpsr_object_Ticker_Keeper` |
| `Ticker.Handle.Tick` | `mdpsr_handle_Ticker_Handle_Tick` |
| `Queue_ticker` | `mdpsr_queue_Queue_ticker` |

> ⚠ `A.B` 和 `A_B` 会推出同一个符号。加载器**不检查**这种冲突，会静默命中
> 其中一个。条目名别在这种地方含糊。

### 2.3 名字长度

上限 `MDPSR_NAME_MAX - 1` = **63 字节**（含终止符共 64）。超了装载直接失败
（`11013`）。诊断用的名字副本会被 `snprintf` 截断到 64，**超长的名字会显示成
一样的字符串** —— 所以别超。

## 三、消息

### 3.1 帧布局

```
偏移   类型       字段
 0     uint64_t   _handle     目标 handle 的哈希
 8     int32_t    _cmd        命令号
12     int32_t    _len        本条消息总字节长 (= 16 + body 长度)
16     uint8_t    body[]      载荷
```

宿主只负责"按 `_handle` 查表，把 Context 和 body 交给 handle"。**body 怎么解析
完全由你自己定**。

### 3.2 你要拿到的两段内存

```cpp
typedef int (*mdpsr_handle_fn)(const uint8_t* msg_data, size_t msg_len,
                               const mdpsr_context* ctx);
```

* `msg_data / msg_len` —— **body**（不含帧头！宿主已经切掉了）。
* `ctx` —— 分发上下文，见下一节。

### 3.3 `cmd` 的约定

| `_cmd` | 约定 |
| --- | --- |
| `0`（`MDPSR_CMD_INIT`） | **初始化，约等于别的框架里的 Main**。组件装载完后宿主会投一条 |
| `>= 1` | 组件自己定义的命令 |
| — | 本身"没有主线"的组件（比如纯工具类）把 `cmd=0` 空着返回 `MDPSR_OK` 就行 |

**点火消息是固定的 16 字节** `{ int32 _cmd; int32 _pad; uint64 _arg; }`。
但**不要假设它只有这一种**：同一条 `cmd` 以后可能带更多字段。

### 3.4 推荐写法（防御式解析）

```cpp
int32_t cmd = MDPSR_CMD_INIT;
if (!mdpsr_read_pod(msgData, msgLen, &cmd)) {   // 连 4 字节都没有
    return MDPSR_ERR_BAD_MESSAGE;
}
// 参数在长度够的时候才读, 不够就用默认值
uint64_t value = 0;
if (msgLen >= sizeof(MyFullCmd)) {
    MyFullCmd full{};
    if (mdpsr_read_pod(msgData, msgLen, &full)) value = full.value;
}

switch (cmd) {
case MDPSR_CMD_INIT: /* ... */ return MDPSR_OK;
case 1:              /* ... */ return MDPSR_OK;
default:             return MDPSR_ERR_UNKNOWN_CMD;
}
```

> **反面教材**：先 `mdpsr_read_pod(msgData, msgLen, &整条结构体)`，失败就返回。
> 这样一条 16 字节的点火消息会被你的组件拒收 —— 而且它**不会变砖**（宿主不会重试
> `cmd=0`），只是永远不工作。骨架早期版本的 ticker 就这么错过）。

### 3.5 变长载荷

定长头 + 尾随字节，就是 DLLMgr / core 用的那套：

```c
struct CoreCmd {
    int32_t  _cmd;
    uint32_t _pad;
    uint64_t _plugin;
    /* char _path[]; 紧跟其后, NUL 结尾 */
};
```

读尾随字符串用 `mdpsr_read_str(msgData, msgLen, sizeof(CoreCmd))`，
它保证不越界，读不到返回 `nullptr`。

## 四、Context：你能看到什么

```c
typedef struct mdpsr_context {
    mdpsr_map* object;   /* 本插件自己的 Object */
    mdpsr_map* state;    /* 全部 State */
    mdpsr_map* handle;   /* 全部 Handle */
    mdpsr_map* queue;    /* 全部 Queue  */
    struct mdpsr_host* host;
} mdpsr_context;
```

**所有指针只在本次调用期间有效**，handle 返回后就别再存了。

### 4.1 查表

二级字典是**宿主的** `HashMap`，你**不要**直接调它的成员（换实现你就崩了）。
用 host api：

```c
mdpsr_ptr* p = H->map_find(ctx->state, mdpsr_hash64("core_State_ResourceDict"));
if (!p) return MDPSR_ERR_NOT_FOUND;          // 没挂 / 已经被卸载置无效

void* payload = H->map_ptr_of(H->host, p);   // 取"里面那个资源指针"
```

`map_count(tbl)` 能拿到表里有多少条（诊断用）。

### 4.2 完整的"取公用数据"姿势

```c
// 1) 查条目
mdpsr_ptr* p = H->map_find(ctx->state, mdpsr_hash64("Ticker.Ticks"));
if (!p) return MDPSR_ERR_NOT_FOUND;

// 2) 快速看一眼有效性 (不持锁, 只是一瞥)
if (!H->map_is_valid(H->host, p)) return MDPSR_ERR_MAP_INVALID;

// 3) 取指针
auto* st = static_cast<TickStats*>(H->map_ptr_of(H->host, p));
if (!st) return MDPSR_ERR_BAD_STATE;

// 4) 真正要"读改写"的时候, 必须持锁 + 复查
if (H->map_lock(H->host, p) != MDPSR_OK) return MDPSR_ERR_BUSY;
if (!H->map_is_valid(H->host, p)) {          // 拿锁期间可能被置无效
    H->map_unlock(H->host, p);
    return MDPSR_ERR_MAP_INVALID;
}
st->sum += value;                            // ← 现在才是安全的
H->map_unlock(H->host, p);
```

> **为什么第 4 步要复查**：`valid` 是"门闸"，但门闸是**在你拿到锁之前**被关掉的。
> 拿锁和关闸之间有一个窗口，不复查就可能用到已经作废的资源。

### 4.3 如果我要改**别的组件**的数据

**这是规范允许的**（State 的定位就是"跨组件公用的配置/数据对象"），但代价自负：

* 对方资源被卸载后你的指针就是悬垂的 —— **每次用都要重新查 + 持锁**。
* 对方的结构体布局由它的头文件定义。你 include 它就产生了**源码级依赖**
  （编译期耦合）。骨架里 `ticker` 就 include 了 `core_mgr.h` 才认得那个结构体。
* 不加锁地改，就是数据竞争 —— 宿主**不会**替你兜（`Ptr.mtx` 是工具，不是自动锁）。

## 五、四类工厂

### 5.1 State 工厂

```cpp
typedef void* (*mdpsr_state_fn)(const mdpsr_factory_ctx* ctx);

MDPSR_EXPORT mdpsr_state* mdpsr_state_Ticker_Ticks(const mdpsr_factory_ctx* ctx) {
    if (!ctx || !ctx->pool || !ctx->host) return nullptr;
    void* mem = ctx->pool->allocate(sizeof(TickStats), alignof(TickStats));
    if (!mem) return nullptr;
    auto* st = new (mem) TickStats{};          // 纯 POD, 不用登记析构
    st->magic = TICKER_MAGIC;
    return static_cast<mdpsr_state*>(st);      // 宿主会把它挂进 MainMap
}
```

* **State 只能是"数值对象 / 公开数据对象"**，从 `ctx->pool`（== `Pool_state`）分配。
* 工厂返回的是 `mdpsr_state*`（签名如此），但**当前骨架把它当成"载荷指针"直接挂进
  MainMap** —— 所以实际上你返回什么，`map_ptr_of` 就拿到什么。`core` 和 `ticker`
  都是直接把 POD 载荷的地址返回。
* `magic` 字段是推荐做法：别的组件拿到你的 State 时能确认"这确实是我的载荷"。

> ⚠ **关于 `mdpsr_state::destroy` 字段**：结构体里有这个字段，但**宿主代码从不调用
> 它**（`Pool_state` 的载荷不做逐条释放）。所以：
>
> * **State 载荷请用纯 POD。** 这样完全没问题。
> * 载荷里若要放 `std::pmr` 容器，它们的节点会留在池里直到进程结束 ——
>   功能上没错，但**频繁装卸同一个插件会累积内存**。
> * 不要把"清理逻辑"押在 `destroy` 上 —— 它现在是装饰品。

### 5.2 Object 工厂

```cpp
MDPSR_EXPORT void* mdpsr_object_Ticker_Keeper(const mdpsr_factory_ctx* ctx) {
    if (!ctx || !ctx->pool || !ctx->host) return nullptr;
    void* mem = ctx->pool->allocate(sizeof(Keeper), alignof(Keeper));
    if (!mem) return nullptr;
    try {
        return new (mem) Keeper(ctx->host, ctx->pool);
    } catch (...) {
        ctx->pool->deallocate(mem, sizeof(Keeper), alignof(Keeper));
        return nullptr;
    }
}

MDPSR_EXPORT void mdpsr_object_Ticker_Keeper_destroy(void* instance) {
    auto* o = static_cast<Keeper*>(instance);
    if (!o) return;
    std::pmr::memory_resource* pool = o->pool();   // ★ 析构前先取池
    o->~Keeper();
    if (pool) pool->deallocate(o, sizeof(Keeper), alignof(Keeper));
}
```

* 析构导出名的约定：**工厂名 + `_destroy`**。找不到就跳过（记一条 WARN，实例漏掉）。
* **池指针必须在析构前取** —— 析构之后对象已经没了，取不到。
* 所以 `Keeper` 必须存一份 `mdpsr_resource* _pool`，并暴露 `pool()` 访问器。

> ⚠ **绝对不要用 `new_object` 配 `delete`。** 对象是池出来的、释放走堆，
> 会直接造成堆损坏。骨架早期版本踩过这个坑。

### 5.3 Handle 工厂（就是消息入口本身）

```cpp
MDPSR_EXPORT int mdpsr_handle_Ticker_Handle_Tick(const uint8_t* msgData, size_t msgLen,
                                                 const mdpsr_context* ctx) {
    if (!ctx || !ctx->host) return MDPSR_ERR_NULLPTR;
    const mdpsr_host* H = ctx->host;
    /* ... 见 3.4 的防御式解析 ... */
}
```

* **必须无状态。** 任何跨消息要保留的东西都放 State 或 Object。
* 返回 `MDPSR_OK`(0) 表示成功；非 0 会被宿主记一条 WARN 并计入 `dispatch_errors`。
* 你**不需要**（也**不应该**）自己去解析帧头。

### 5.4 Queue 工厂（可选）

```cpp
MDPSR_EXPORT int mdpsr_queue_Queue_ticker(const mdpsr_factory_ctx* ctx,
                                          mdpsr_queue_desc* out) {
    if (!ctx || !out) return MDPSR_ERR_NULLPTR;
    out->struct_size = sizeof(mdpsr_queue_desc);
    out->capacity    = 4096;   // 初始环形缓冲字节, 0 = 默认 4096
    out->pace_ms     = 20;     // ★ 两条消息的处理开始时间至少隔 20ms
    out->reserved    = 0;
    return MDPSR_OK;           // 返回非 OK = 拒绝建立这条队列 (宿主跳过)
}
```

* 工厂**不是必须的**：在 `Queue` 段只写名字，就用默认参数。
* **`pace_ms` 是这套骨架给你的限速器。** 需要"常驻循环"的组件应该用它，
  而不是在自己代码里 `sleep` —— 尤其是在主线程队列上，`sleep` 会堵死消息泵。

## 六、`plugin.json`

### 6.1 完整形状

```jsonc
{
  "name":     "ticker",                 // 插件名。必填, <= 63 字节
  "dll_path": ["mdpsr_ticker.dll"],     // 相对【本清单所在目录】; 字符串或数组

  "State":  ["Ticker.Ticks"],           // 可选
  "Object": ["Ticker.Keeper"],          // 可选
  "Handle": ["Ticker.Handle.Tick"],     // 必填, 至少一个
  "Queue":  ["Queue_ticker"],           // 可选; 省略就用 Queue_default
  "Init":   "Ticker.Handle.Tick"        // 可选; 写了必须指向声明过的 Handle
}
```

### 6.2 字段规则

| 字段 | 规则 |
| --- | --- |
| `name` | 必填。也是 `plugin:<name>` 这个插件条目的名字来源 |
| `dll_path` | 相对**本清单所在目录**。数组里每个 dll 都会 `LoadLibrary` 并收到一次 `mdpsr_module_init` |
| `State` / `Object` / `Handle` / `Queue` | 接受 `"X"` 或 `["X","Y"]`。元素必须是字符串 |
| `Init` | 可选。**必须**指向 `Handle` 里声明过的条目，否则装载失败（`11002`） |
| 条目名 | **全局唯一**。与 `MainMap` 的键空间共用（handle 与 object 不能同名） |

### 6.3 路径基准

* `dll_path` 相对**清单所在目录** —— 所以 `build/core/plugin.json` 里写
  `"mdpsr_core.dll"` 就能找到同目录的 dll。
* 运行时其它地方（`config.json` 的 `plugin` 列表、`host->plugin_load` 的参数）
  用的是**相对运行时根目录**（也就是 exe 所在目录）。
* 工厂里拿到相对路径要拼的时候用 `mdpsr_path_join(out, cap, ctx->manifest_dir, rel)`，
  它会消解 `.` / `..`。

### 6.4 JSON 是严格的

解析器**只读**而且**严格**：

* 不支持注释、尾随逗号、单引号。
* 顶层值之后**不允许**有多余内容（`{...} 这不是 json` 会直接报错）。
* 数字格式非法（`1.2.3.4e+`）会报错。
* 允许：UTF-8 BOM、`\uXXXX` 转义（含代理对）。

## 七、Host API 速查

`ctx->host` 指向它。所有函数第一个参数是 `host->host`（宿主实例，原样回传）。

### 7.1 基础

| 函数 | 说明 |
| --- | --- |
| `hash(name)` | 与宿主一致的 64 位哈希（不过一般直接用 `mdpsr_hash64`） |
| `log(host, level, msg)` | `0` INFO / `1` WARN / `2` ERR / `3` DBG |
| `root_dir(host)` | 运行时根目录（UTF-8），exe 所在目录 |

### 7.2 MainMap

| 函数 | 说明 |
| --- | --- |
| `map_get(host, key)` | 按键查**有效**条目。`valid == false` 或不存在 → `NULL` |
| `map_is_valid(host, p)` | 原子读一下 `valid`。不持锁，只是"看一眼" |
| `map_lock` / `map_try_lock` / `map_unlock` | `Ptr.mtx`。**"我在用这个资源"的唯一声明方式** |
| `map_ptr_of(host, p)` | 取 `Ptr` 里的资源指针 |
| `map_attach(host, kind, key, name, ptr, &out)` | 挂进 MainMap。`kind` 见下 |
| `map_detach(host, key)` | 摘表（要在**持有该条目锁**的前提下调用） |
| `map_invalidate(host, key)` | 置 `valid = false`（卸载第一步） |
| `map_enum_keys(host, out, cap, &n)` | 枚举全部键的快照 |
| `map_find(tbl, key)` | **查二级字典**（`ctx->state` 等）。这是你查表的正常姿势 |
| `map_count(tbl)` | 二级字典里有多少条 |

`kind` 取值：`MDPSR_KIND_OBJECT(0)` / `STATE(1)` / `HANDLE(2)` / `QUEUE(3)`。
它决定条目进哪张二级字典。

### 7.3 插件装载（一般只有 core 用）

| 函数 | 说明 |
| --- | --- |
| `plugin_load(host, manifest_rel, &plugin)` | 全套装载。`manifest_rel` 相对运行时根目录 |
| `plugin_unload(host, plugin)` | 全套卸载。可能返回 `PLUGIN_BUSY`（有人正在用） |
| `plugin_keys(host, plugin, out, cap, &n)` | 这个插件在 MainMap 里占的全部键（**不含**插件条目自身） |
| `init_handle_of(host, plugin, out, cap)` | 这个插件声明的 Init handle 名字（没有就是空串） |

### 7.4 消息

| 函数 | 说明 |
| --- | --- |
| `emit(host, handle_key, body, len)` | 按目标 handle 绑定的队列投递；没有就落到它所属插件的默认队列，再没有就 `Queue_default` |
| `queue_emit(host, queue_key, handle_key, body, len)` | 明确投到某条队列。查不到就回落到 `Queue_default` |

> `_cmd` **不用你填** —— 宿主从 `body` 的前 4 字节取。

### 7.5 队列 / 主线程

| 函数 | 说明 |
| --- | --- |
| `queue_create(host, name, desc, plugin, &out)` | **后门级**：建一条队列（幂等）。只有 core 该用 |
| `queue_bind(host, handle_key, queue_key)` | 把 handle 绑到某条队列 |
| `queue_key_for_plugin(host, plugin)` | 这个插件默认去的那条队列的键 |
| `queue_get(host, queue_key)` | 按队列键取 `Ptr` |
| `queue_list(host, out, cap, &n)` | 全部队列键的快照 |
| `main_thread_id(host)` | 宿主主线程 id。和自己 `GetCurrentThreadId()` 比就知道在不在主线上 |

### 7.6 上下文里的 `mdpsr_factory_ctx`

工厂拿到的不是 `mdpsr_context`，而是它：

| 字段 | 说明 |
| --- | --- |
| `name` | 条目名 |
| `plugin_name` | 插件名（清单的 `name`） |
| `manifest` / `manifest_dir` | 本清单相对根目录的路径 / 所在目录 |
| `list` / `list_count` | 清单里的字符串数组（当前骨架**不填**，恒为 `NULL` / 0） |
| `plugin` | 本插件在 MainMap 里的键 |
| `host` | host api |
| **`pool`** | ★ **该用哪个池**：State 工厂 → `Pool_state`；Object 工厂 → `Pool_object`；Queue 工厂 → `Pool_msg` |

## 八、最小完整示例

一个能跑的最小插件：一个 State（计数）、一个 Handle（收到 `cmd=1` 就 +1）。

### `my_counter.h`

```cpp
#pragma once
#include "mdpsr/abi.h"

#define MY_COUNTER_MAGIC 0x4D594331u   /* 'MYC1' */

struct MyCounter {
    uint32_t magic;
    uint32_t reserved;
    uint64_t value;
};
```

### `my_plugin.cpp`

```cpp
#include "my_counter.h"
#include <new>

/* ---- State: 纯 POD, 从 Pool_state 分配 ---- */
MDPSR_EXPORT mdpsr_state* mdpsr_state_My_Counter(const mdpsr_factory_ctx* ctx) {
    if (!ctx || !ctx->pool) return nullptr;
    void* mem = ctx->pool->allocate(sizeof(MyCounter), alignof(MyCounter));
    if (!mem) return nullptr;
    auto* c = new (mem) MyCounter{};
    c->magic = MY_COUNTER_MAGIC;
    return static_cast<mdpsr_state*>(c);
}

/* ---- Handle: 无状态入口 ---- */
MDPSR_EXPORT int mdpsr_handle_My_Main(const uint8_t* msgData, size_t msgLen,
                                      const mdpsr_context* ctx) {
    if (!ctx || !ctx->host) return MDPSR_ERR_NULLPTR;
    const mdpsr_host* H = ctx->host;

    /* 判分只读 _cmd —— 宿主点火只给 16 字节 */
    int32_t cmd = MDPSR_CMD_INIT;
    if (!mdpsr_read_pod(msgData, msgLen, &cmd)) return MDPSR_ERR_BAD_MESSAGE;

    /* 拿公用数据: 查 -> 看一眼有效 -> 取指针 */
    mdpsr_ptr* p = ctx->state ? H->map_find(ctx->state, mdpsr_hash64("My.Counter")) : nullptr;
    if (!p) return MDPSR_ERR_NOT_FOUND;
    auto* c = static_cast<MyCounter*>(H->map_ptr_of(H->host, p));
    if (!c || c->magic != MY_COUNTER_MAGIC) return MDPSR_ERR_BAD_STATE;

    if (cmd == MDPSR_CMD_INIT) {
        /* 要"读改写"就持锁 + 复查 */
        if (H->map_lock(H->host, p) != MDPSR_OK) return MDPSR_ERR_BUSY;
        if (H->map_is_valid(H->host, p)) c->value = 0;
        H->map_unlock(H->host, p);

        /* 没有别的活 -> 把 cmd=1 回滚给自己, 循环转起来 */
        uint32_t one = 1;
        return H->emit(H->host, mdpsr_hash64("My.Main"), &one, sizeof(one));
    }
    if (cmd == 1) {
        if (H->map_lock(H->host, p) != MDPSR_OK) return MDPSR_ERR_BUSY;
        if (H->map_is_valid(H->host, p)) c->value++;
        H->map_unlock(H->host, p);
        /* 为演示简洁, 这里不继续回滚 —— 真实组件要么有终止条件,
         * 要么在自己的队列上声明 pace_ms 限速 */
        return MDPSR_OK;
    }
    return MDPSR_ERR_UNKNOWN_CMD;
}

/* ---- 模块导出 ---- */
MDPSR_EXPORT uint32_t mdpsr_abi_version(void) { return MDPSR_ABI_VERSION; }

MDPSR_EXPORT int mdpsr_module_init(const mdpsr_host* host, uint64_t plugin) {
    if (!host) return MDPSR_ERR_NULLPTR;
    if (host->abi_version != MDPSR_ABI_VERSION) return MDPSR_ERR_PLUGIN_ABI;
    if (host->struct_size < sizeof(mdpsr_host)) return MDPSR_ERR_PLUGIN_ABI;
    return MDPSR_OK;
}

MDPSR_EXPORT void mdpsr_module_fini(uint64_t plugin) { (void)plugin; }
```

## 九、常见坑对照表

| 现象 | 多半是 |
| --- | --- |
| 装载日志里 `Handle 'X' 注册失败 (rc=11010)` | **条目名撞键**了（handle 与 object 同名？和别的插件撞名？） |
| `找不到导出 mdpsr_handle_X` | 条目名到符号的规范化对不上（点号/横杠没变成下划线？） |
| 组件装载成功但**什么都不干** | `cmd=0` 被你的长度校验拒收了（要求整条结构体，而点火只有 16 字节） |
| 组件能跑但**看不到别的组件的 State** | `config.json` 里插件顺序排反了 |
| 退出码 `0xC0000374` | **堆损坏** —— Object 析构用了 `delete` 而不是还回池 |
| `plugin_unload` 一直返回 `13005` | 有人一直持着锁（长阻塞的 handle？忘记 `map_unlock`？） |
| 卸载时死锁 | 在自己的队列线程上卸载自己 |
| 主线程卡住 / 界面冻住 | 在 `Queue_windowsgui` 上 `sleep` 了 |
| CPU 空转 | 自转循环没有终止条件，也没在队列上声明 `pace_ms` |
| 数据偶尔错乱 | 跨线程改 State 却没持锁（`Ptr.mtx` 不是自动锁） |

## 十、发布前自查

- [ ] `mdpsr_abi_version` / `mdpsr_module_init` 都导出了
- [ ] 每个 Handle 都是无状态的（没有任何可变全局量）
- [ ] 载荷判分只读前 4 字节，参数在长度够时才读
- [ ] 每个 `map_ptr_of` 的结果都判了空
- [ ] 工厂全部用 `ctx->pool` 分配；Object 析构先取池再 `deallocate`
- [ ] 工厂和 handle 内部都有 `try/catch`，异常不穿过 dll 边界
- [ ] 条目名全局唯一，且规范化后不冲突
- [ ] 要循环的组件有终止条件，或在自己的队列上声明了 `pace_ms`
- [ ] 没有在自己的队列线程上卸载自己
- [ ] 没有跨 dll 传非 POD 的载荷
- [ ] `plugin.json` 的 `Init` 指向确实声明过的 Handle
