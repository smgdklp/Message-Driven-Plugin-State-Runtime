# DLL 插件规范声明

> 文档索引：[项目说明](项目说明.md) · [插件规范](插件规范.md) · [DLLMgr 内核组件](DLLMgr内核组件.md)
>
> **ABI 版本：`MDPSR_ABI_VERSION = 3`**
> 唯一契约文件：`include/mdpsr/abi.h`。本文是它的自然语言声明，
> 两者冲突时**以 `abi.h` 为准**。

---

## 0. 术语

| 词 | 含义 |
| --- | --- |
| 宿主 / Runtime | `mdpsr.exe`，负责池、队列、Map、分流分发、装载 |
| 插件 / 组件 | 一个 DLL + 一份 `plugin.json` |
| 清单 / manifest | `plugin.json`，声明这个 DLL 导出哪些 state / object / handle，以及要申请哪些分流队列 |
| 条目 / entry | 清单里的一条声明，注册进 Map 后有一个唯一的 64 位键 |
| 分流队列 | `Map` 里的第四类条目 `Queue*`；每条队列配一个 Dispatcher 和一条常驻线程 |
| 运行时根目录 | 宿主 exe 所在目录；所有相对路径都以它为基准 |
| 后门 | 宿主读完 `config.json` 后**直接调用**（不走消息队列）的初始化函数，见 [第 7 节](#7-后门函数) |

---

## 1. 插件包形态

一个插件就是一个目录（推荐自包含）：

```
build/capture/                 ← 插件包
├── mdpsr_capture.dll          ← 实现（清单里 dll_path 指向它）
├── plugin.json                ← 清单
└── opencv_world500.dll        ← 该插件自己的依赖（可选）
```

宿主通过清单路径找到它：`config.json` 里写 `"core/plugin.json"`，
内核 DLLMgr 里写 `"../capture/plugin.json"`——**都是相对运行时根目录**的路径。

## 2. 必需导出

```cpp
#include <mdpsr/abi.h>

MDPSR_EXPORT uint32_t mdpsr_abi_version(void);                          // 必须
MDPSR_EXPORT int      mdpsr_module_init(const mdpsr_host* host,
                                        uint64_t dll);                  // 必须
MDPSR_EXPORT void     mdpsr_module_fini(uint64_t dll);                  // 可选
```

| 符号 | 约定 |
| --- | --- |
| `mdpsr_abi_version` | 返回 `MDPSR_ABI_VERSION`。宿主 `LoadLibrary` 后会轮询最多 3 秒等它，不匹配就拒绝加载 |
| `mdpsr_module_init` | 在**所有工厂被调用之前**执行。只做校验与记录，返回 `MDPSR_OK` 或其他错误码；这里**不要**注册 Map 条目（注册由宿主按清单统一做） |
| `mdpsr_module_fini` | `FreeLibrary` 之前调用。可选 |

> `MDPSR_EXPORT` = `extern "C" __declspec(dllexport)`
> （非 Windows 上展开成 `__attribute__((visibility("default")))`）。

**绝不允许 C++ 异常穿过 DLL 边界**：工厂和 handle 内部自己 `try/catch`，
失败返回错误码或 `nullptr`。

## 3. 清单 `plugin.json`

### 3.1 完整形状

```jsonc
{
  "dll_path": ["mdpsr_xxx.dll"],          // 字符串或字符串数组

  "queue": {                              // 可选: 组件自己申请的分流队列
    "Capture.Thread": {                   // 队列名 (会挂到 Map.Queue* 上)
      "symbol":   "mdpsr_queue_capture",  // 可选: queue 工厂; 省略就用默认参数
      "capacity": 8192,                   // 可选: 初始环形缓冲字节, 0 = 默认 4096
      "param":    "…"                     // 可选: 字符串 或 字符串数组
    },
    "mdpsr_queue_other": "Other.Thread"   // 简写: 键是 symbol, 值是队列名
  },

  "state": {
    "条目名称": {
      "symbol": "mdpsr_state_xxx",        // 导出函数名
      "param":  "./test/img"              // 可选: 字符串 或 字符串数组
    },
    "另一个state": "mdpsr_state_yyy"      // 简写: 只给 symbol
  },

  "object": {
    "条目名称": {
      "symbol": "mdpsr_object_xxx",
      "param":  "…"
    }
  },

  "handle": {
    "条目名称": {
      "symbol": "mdpsr_handle_xxx",
      "type":   "handle",                 // "handle" | "handle_core", 默认 handle
      "state":  "主state名称",            // 可选: 主 state (= states[0])
      "states": ["A", "B", "C"],          // 可选: 绑定的全部 state, 最多 4 个
      "object": "绑定的object名称",       // 可选
      "queue":  "分流队列名"              // 可选: 省略 = queue_core
    }
  }
}
```

### 3.2 字段规则

| 字段 | 规则 |
| --- | --- |
| `dll_path` | 相对**本清单所在目录**；可以是字符串或数组。数组里每个 DLL 都会 `LoadLibrary` 并收到一次 `mdpsr_module_init` |
| 条目名 | **全局唯一**。Map 的键 = `mdpsr_hash64(条目名)`，重名会拿到 `MDPSR_ERR_ALREADY_EXISTS`。同一份清单里 handle 与 object 不能同名 |
| `symbol` | 省略时默认等于条目名（`queue` 段例外：symbol 可以整个省略） |
| `type` | 只对 handle 有意义；`"handle_core"` / `"core"` 走 `CoreContent`，其余走 `Content` |
| `param` | 字符串 → 工厂收到 `ctx->param`；数组 → 收到 `ctx->list` / `ctx->list_count` |
| `state` / `states` | `state` 是主 state（`Content::state`）；`states` 是全部绑定。两者可同时写，会自动去重，顺序是 `state` 在前 |
| `object` | 绑定的 object；`Content::classptr` 会指向它的 `mdpsr_classptr` |
| `queue` 段 | 两种写法：常规 `{ "队列名": { "symbol": …, "capacity": … } }`；简写 `{ "symbol": "队列名" }`。宿主会为每条队列建一个 `Queue` + 一个 `Dispatcher` + **一条常驻线程**，队列名挂到 `Map.Queue*` |
| handle 的 `queue` | 把 handle 绑到某条分流队列；**省略、或者名字找不到对应队列，都回退 `queue_core`** |

### 3.3 路径基准（重要）

* 清单里的 `dll_path`：相对**本清单所在目录**。
* 清单里的 `param` 里的相对路径：**不做任何解释**，原样传给工厂。
  工厂需要把它变成"相对运行时根目录"的形式时，用：

  ```c
  char buf[MDPSR_PATH_MAX];
  mdpsr_path_join(buf, sizeof(buf), ctx->manifest_dir, ctx->param);
  // "core" + "../capture/plugin.json"  ->  "capture/plugin.json"
  ```

* 宿主所有对外路径接口（`plugin_load`、`manifest_*`）收发的都是
  **相对运行时根目录**的 UTF-8 路径。

## 4. State 工厂

```cpp
typedef mdpsr_state* (*mdpsr_state_fn)(const mdpsr_state_ctx* ctx);
MDPSR_EXPORT mdpsr_state* mdpsr_state_xxx(const mdpsr_state_ctx* ctx);
```

### 4.1 上下文

```c
typedef struct mdpsr_state_ctx {
    const char*              name;          // 条目名 (json 的 key)
    const char*              param;         // param 是字符串时有值, 否则 NULL
    const char* const*       list;          // param 是数组时有值, 否则 NULL
    size_t                   list_count;
    const char*              manifest;      // 本清单相对根目录的路径
    const char*              manifest_dir;  // 本清单所在目录 (相对根目录)
    uint64_t                 dll;           // 本插件的 dll 键
    mdpsr_resource*          pool;          // ★ Pool_state (全局公共池)
    const struct mdpsr_host* host;          // 宿主服务接口
    void*                    reserved;      // 保留, 现在恒为 NULL
} mdpsr_state_ctx;
```

### 4.2 返回值与生命周期

返回的 `mdpsr_state*` 由宿主接管：

* 宿主会覆盖 `st->name = hash(条目名)`、`st->dll = ctx->dll`，然后注册进 Map；
* **卸载时**宿主调 `mdpsr_state_delete(st)`，它会先跑 `st->destroy`（如果设了），
  再释放 `payload` 和 `st` 本身；
* 所以载荷里如果放了 C++ 对象（`std::pmr::map` 之类），**必须**设 `destroy` 来跑析构。

### 4.3 推荐写法

```cpp
struct Config {                       // 公用数据对象
    std::pmr::map<uint64_t, Entry*> table;
    explicit Config(std::pmr::memory_resource* r) : table(r) {}
};

template <typename T>
static void destroy_payload(mdpsr_state* st) {
    static_cast<T*>(st->payload)->~T();
}

MDPSR_EXPORT mdpsr_state* mdpsr_state_config(const mdpsr_state_ctx* ctx) {
    if (!ctx || !ctx->pool) return nullptr;

    mdpsr_state* st = mdpsr_state_new(ctx->pool, /*kind*/0x43464731u, sizeof(Config));
    if (!st) return nullptr;

    new (st->payload) Config(ctx->pool);        // 在 Pool_state 里构造
    st->destroy = &destroy_payload<Config>;     // 登记析构
    return st;
}
```

要点：

* **一定**用 `ctx->pool`（= `Pool_state`）分配，不要用 `new`/`malloc`——
  否则卸载时宿主无法回收。
* `kind` 填一个你自己定义的四字节标签（'CFG1' 之类），方便别的插件辨认载荷。
* 纯 POD 载荷不需要 `destroy`，`mdpsr_state_new(ctx->pool, kind, sizeof(T))` 后
  直接往 `st->payload` 上写即可。

### 4.4 State 的读写与并发

分配 State 时 `st->res` 记录的是分配它的池。改动 State 载荷时要自己保证
"先声明在读/在写"：

```c
void* p = nullptr;
if (host->map_lookup(host->host, key, &p, /*write*/1) == MDPSR_OK) {
    mdpsr_state* st = (mdpsr_state*)p;
    ...改载荷...
    host->map_release(host->host, key, /*write*/1);
}
```

`map_wait_idle` / `dll_idle` 会等到 `r_count == w_count == 0`，
卸载流程就是靠它保证"没人再用"。

> **多线程提醒**：`Pool_state` 已经是 `synchronized_pool_resource`，
> 所以多个分发线程可以并发从它分配；但**载荷内容**的并发保护仍然要你自己做
> （`map_lookup(..., write=1)` 只是记账，不是锁）。

## 5. Object 工厂

```cpp
typedef void* (*mdpsr_object_fn)(const mdpsr_object_ctx* ctx);
MDPSR_EXPORT void* mdpsr_object_xxx(const mdpsr_object_ctx* ctx);          // 必须
MDPSR_EXPORT void  mdpsr_object_xxx_destroy(void* instance);               // 可选
```

* 上下文 `mdpsr_object_ctx` 与 `mdpsr_state_ctx` **字段完全一致**，唯一区别是
  `pool` 指向**该 DLL 的专属池**（`Pool_dll` 里那一个），不是 `Pool_state`。
* **只返回一个类实例**，宿主会把它包成 `mdpsr_classptr` 注册进 Map。
* 析构函数是可选的，命名约定：**object 工厂名 + `_destroy`**。
  宿主在 `GetProcAddress` 里按这个约定找；找到就在卸载时调用，找不到就跳过。
* 因为实例是在专属池里 `new` 出来的，析构函数要能自己找回那个池：

```cpp
class Worker {
public:
    Worker(std::pmr::memory_resource* pool, const mdpsr_host* host)
        : _pool(pool), _host(host) {}
    std::pmr::memory_resource* Pool() const { return _pool; }
    // ...
private:
    std::pmr::memory_resource* _pool;
    const mdpsr_host*          _host;
};

MDPSR_EXPORT void* mdpsr_object_worker(const mdpsr_object_ctx* ctx) {
    if (!ctx || !ctx->pool) return nullptr;
    try {
        std::pmr::polymorphic_allocator<Worker> a(ctx->pool);
        return a.new_object<Worker>(ctx->pool, ctx->host);
    } catch (...) { return nullptr; }
}

MDPSR_EXPORT void mdpsr_object_worker_destroy(void* instance) {
    auto* w = static_cast<Worker*>(instance);
    if (!w) return;
    std::pmr::memory_resource* pool = w->Pool();
    std::pmr::polymorphic_allocator<Worker> a(pool);
    a.delete_object(w);
}
```

> **类实例只允许它的宿主 DLL 自己碰。** 别的组件要数据请走 State——
> 这是 [State 约定](项目说明.md#32-state-是公用配置--公用数据对象)存在的意义。

## 6. Queue 工厂（分流队列）

组件在清单的 `queue` 段申请自己的分流队列之后，宿主会：建一个 `Queue`
（环形缓冲，从 `Pool_msg` 分配）、建一个 `Dispatcher`（放进 `Pool_dispatcher`）、
从 `Pool_thread` 拿一条**常驻线程**跑它，并把队列名以 `Map.Queue*` 注册进 Map。
从此**发给绑在它上面的 handle 的消息，都在那条线程上执行**。

```cpp
typedef int (*mdpsr_queue_fn)(const mdpsr_queue_ctx* ctx, mdpsr_queue_desc* out);
MDPSR_EXPORT int mdpsr_queue_xxx(const mdpsr_queue_ctx* ctx, mdpsr_queue_desc* out);
```

### 6.1 上下文

`mdpsr_queue_ctx` 的字段与 `mdpsr_state_ctx` / `mdpsr_object_ctx` **完全一致**，
唯一区别是 `pool` 指向 **`Pool_msg`**（队列本体用的池）：

```c
typedef struct mdpsr_queue_ctx {
    const char*              name;          // 队列名 (json 的 key)
    const char*              param;         // param 是字符串时有值, 否则 NULL
    const char* const*       list;          // param 是数组时有值, 否则 NULL
    size_t                   list_count;
    const char*              manifest;
    const char*              manifest_dir;
    uint64_t                 dll;
    mdpsr_resource*          pool;          // ★ Pool_msg
    const struct mdpsr_host* host;
    void*                    reserved;
} mdpsr_queue_ctx;
```

### 6.2 描述符

```c
typedef struct mdpsr_queue_desc {
    uint32_t struct_size;   // 填 sizeof(mdpsr_queue_desc)
    uint32_t flags;         // 保留, 填 0
    uint32_t capacity;      // 初始环形缓冲字节数, 0 = 用默认值
    uint32_t reserved;
} mdpsr_queue_desc;
```

### 6.3 约定

* **返回 `MDPSR_OK` 表示允许建立这个分流队列**；返回别的值，
  宿主会打一条 WARN 并**跳过**这个队列（那个 handle 后续会回退到 `queue_core`）。
* 工厂**不是必须的**：条目只给队列名（或简写形式只给 symbol），
  宿主就用默认参数（容量 4096）建队列。
* 清单里的 `capacity` 与工厂写的 `desc.capacity` 同时存在时，**以工厂写的为准**。
* **生命周期**：队列从属于声明它的那个 dll。dll 卸载时，宿主会先置停它的
  dispatcher 线程、**在锁外 join**、再释放 `Dispatcher` → `Queue` → `mdpsr_queue`
  描述符，最后摘掉 `Map.Queue*` 条目。
* 队列名也是**全局唯一**的 Map 键（`hash(队列名)`），和其它条目共享同一个键空间。

一个最小的 queue 工厂：

```cpp
MDPSR_EXPORT int mdpsr_queue_capture(const mdpsr_queue_ctx* ctx, mdpsr_queue_desc* desc) {
    if (!ctx || !desc) return MDPSR_ERR_NULLPTR;
    desc->struct_size = static_cast<uint32_t>(sizeof(mdpsr_queue_desc));
    desc->flags       = 0;
    desc->capacity    = 8192;       // 截屏消息比较密, 缓冲开大一点
    return MDPSR_OK;
}
```

## 7. 后门函数

宿主读完 `config.json` 之后，会按里面的 `"init_cmd"` **标签**，在所有已加载模块里
`GetProcAddress` 找同名导出，然后**直接调用它** —— **不经过消息队列**。

```c
typedef int (*mdpsr_backdoor_fn)(const struct mdpsr_host* host);
```

* 标签就是导出名本身。当前项目的 `config.json` 写的是 `"init_cmd": "DLL_init"`，
  对应内核组件 DLLMgr 导出的 `DLL_init`。
* 宿主遍历**所有已加载模块**，谁先导出就用谁；都找不到就返回
  `MDPSR_ERR_NOT_FOUND` 并打一条 ERR 日志。
* 后门用 `mdpsr_host` 里的**后门级接口**干活，主要是：

  | 接口 | 作用 |
  | --- | --- |
  | `queue_create(host, name, capacity, dll, &q)` | 建一条分流队列（含 Dispatcher 与常驻线程），幂等 |
  | `queue_bind(host, handle_key, q)` | 把某个 handle 绑到这条队列 |
  | `queue_emit(host, q, handle_key, body, len)` | 往指定队列投一条消息 |
  | `queue_core(host)` | 取默认队列 `queue_core` |
  | `dispatcher_count(host)` | 当前分流线程数 |

* 库里可以有多个后门，用不同标签区分；`config.json` 一次只指定一个。

最典型的后门就是内核的 `DLL_init`（建立 `queue_core` → 绑内核 handle →
投出第一条 `cmd=0`），细节见
[DLLMgr 内核组件](DLLMgr内核组件.md#5-后门-dll_init)。

## 8. Handle

```cpp
typedef int (*mdpsr_handle_fn)(const uint8_t* msg_data, size_t msg_len,
                               const uint8_t* ctx_data, size_t ctx_len);
MDPSR_EXPORT int mdpsr_handle_xxx(const uint8_t* msgData, size_t msgLen,
                                  const uint8_t* ctxData, size_t ctxLen);
```

### 8.1 硬性要求

1. **必须无状态**：不依赖、不修改任何可变全局量。
2. 只通过 `msgData / msgLen`（消息字节流）与 `ctxData / ctxLen`（上下文）工作。
3. 返回 `MDPSR_OK`(0) 表示成功，非 0 走错误码表。宿主会在返回非 0 时打日志。
4. 你自己负责解释字节流。**长度校验是必须的**，用现成的助手：

```cpp
mdpsr_content cc{};
if (!mdpsr_read_pod(ctxData, ctxLen, &cc)) return MDPSR_ERR_NULLPTR;   // 长度不够

mdpsr_ctrl_msg m{};
if (!mdpsr_read_pod(msgData, msgLen, &m)) return MDPSR_ERR_BAD_MESSAGE;

const char* text = mdpsr_read_str(msgData, msgLen, sizeof(mdpsr_ctrl_msg));  // 可能为 nullptr
```

5. 线程：handle 由**它绑定的那条分流队列的常驻线程**调用。
   同一队列上的消息天然串行，但**不同队列是真并发**；
   插件自己起的线程（截屏的保存线程、cmd 的窗口消息泵线程）也随时可能在跑，
   所以 handle 与那些线程共享的东西要自己加锁。

### 8.2 上下文

```c
typedef struct mdpsr_state_slot { uint64_t key; mdpsr_state* state; } mdpsr_state_slot;
typedef struct mdpsr_queue_table { mdpsr_queue** items; size_t count; } mdpsr_queue_table;

// type = "handle"
typedef struct mdpsr_content {
    mdpsr_state*             state;        // = states[0], 没绑就是 NULL
    mdpsr_classptr*          classptr;     // 绑定的 object, 没绑就是 NULL
    struct mdpsr_host*       host;         // 宿主服务接口
    mdpsr_state_slot*        states;       // ★ 全部绑定的 state
    size_t                   state_count;
    mdpsr_queue*             queue;        // ★ 发起本次分发的 Map.Queue*
} mdpsr_content;

// type = "handle_core"
typedef struct mdpsr_core_content {
    mdpsr_state*             state;
    mdpsr_classptr*          classptr;
    mdpsr_handle*            handle;       // 自己
    mdpsr_handle_core*       handle_core;  // 自己 (含 user 私有字段)
    mdpsr_classptr_table*    classptr_all; // 全部 object 的快照
    mdpsr_dllptr*            dllptr;       // 自己所属的专属池
    struct mdpsr_host*       host;
    mdpsr_state_slot*        states;
    size_t                   state_count;
    mdpsr_queue*             queue;        // 发起本次分发的 Map.Queue*
    mdpsr_queue_table*       queue_all;    // 全部分流队列的快照
} mdpsr_core_content;
```

* `queue` 就是**发起本次分发的那条分流队列**，所有组件都能拿到它。
  想"把活儿留在自己的线程上"就往它里面投：

  ```c
  host->queue_emit(host->host, cc.queue, mdpsr_hash64("My.Handle"), &msg, sizeof(msg));
  ```

* 按名字取 state 的助手：

  ```cpp
  mdpsr_state* st = mdpsr_find_state(cc.states, cc.state_count, "Capture.SavePath");
  Config* cfg = mdpsr_state_as<Config>(st);      // static_cast<Config*>(st->payload)
  ```
* **`states` / `classptr_all` / `queue_all` / `queue` 指向的东西都只在本次调用期间有效**，
  调用返回后失效，别存下来。
* `handle_core` 比 `handle` 多的就是"看得见整个 Map（含全部分流队列）"的能力，
  一般插件用 `handle` 就够了。

## 9. 消息约定

### 9.1 帧格式

```
偏移 0    int32_t  _len      本条消息的总字节长 (= 12 + body)
偏移 4    uint64_t _handle   目标 handle 的哈希值
偏移 12   uint8_t  _buffer[] body, 由收件组件自己解释
```

投递有两个入口：

```c
// 1) 按目标 handle 绑定的分流队列投递; 找不到/投不进就回退 queue_core
int (*emit)(void* host, uint64_t handle_key, const void* body, size_t len);

// 2) 明确投到某条分流队列; q 为 NULL 或投递失败同样回退 queue_core
int (*queue_emit)(void* host, mdpsr_queue* q, uint64_t handle_key,
                  const void* body, size_t len);
```

`handle_key` 一般写 `mdpsr_hash64("目标handle名")`。

> **`emit` 的语义**：先看目标 handle 的 `bind_queue`，
> 有就投给那条队列；没有绑定、队列找不到、或者队列失效，就投给 `queue_core`。
> **"绑了队列但投不进去"**时会累加宿主的 `fallback_total` 计数，方便排查；
> 压根没绑队列的（默认组件）直接走 `queue_core`，不算回退。

### 9.2 通用控制载荷

`abi.h` 提供的默认载荷，宿主脚本 / 插件之间互发消息都用它：

```c
typedef struct mdpsr_ctrl_msg {
    int32_t  cmd;                  // 命令号
    int32_t  flags;
    uint64_t arg;                  // 整数参数 (常见: HWND / 计数 / 序号)
    char     text[MDPSR_TEXT_MAX]; // 240 字节, NUL 结尾
} mdpsr_ctrl_msg;                  // sizeof = 256
```

### 9.3 自定义载荷

插件可以完全自定义字节流布局，只要：

* 用 POD / 显式序列化，别塞 `std::string`、指针、虚表之类跨不了边界的东西；
* 变长部分放在定长头后面（像 DLLMgr 的 `char _path[]` 那样）；
* 在文档或头文件里写清楚；
* 收的一方严格校验长度。

## 10. 宿主服务接口 `mdpsr_host`

`ctxData` 里的 `host` 字段指向它（`ctx->host`）。所有函数第一个参数是
`host->host`（宿主实例，原样回传）。

| 分组 | 函数 | 说明 |
| --- | --- | --- |
| 基础 | `hash(name)` | 与宿主一致的 64 位哈希（FNV-1a 变体，0 映射为 1） |
| | `log(host, level, msg)` | `level`: 0 INFO / 1 WARN / 2 ERR / 3 DBG |
| | `root_dir(host)` | 运行时根目录（UTF-8） |
| 池 | `pool_state(host)` | 全局公共池，**State 就该从这里分配** |
| | `pool_map(host)` | Map 专用池 |
| | `pool_msg(host)` | 消息字节流 / 分流队列专用池 |
| Map | `map_register(host, entry)` | 注册条目（宿主自己也在用） |
| | `map_lookup(host, key, &ptr, write)` | 取条目并 `r_count++` 或 `w_count++` |
| | `map_release(host, key, write)` | 对应的 `--` |
| | `map_invalidate(host, key)` | 置 `valid = 0` |
| | `map_erase(host, key)` | 摘除条目 |
| | `map_wait_idle(host, key, ms)` | 等这个键的读写计数归零 |
| | `map_dll_idle(host, dll, ms)` | 等这个 dll 所有键归零 |
| | `map_snapshot(host, dll, out, cap, &n)` | 快照（`dll=0` 表示全部） |
| DLL 池 | `dll_pool_create / get / release` | 专属池的建 / 查 / 整池释放 |
| 消息 | `emit(host, handle_key, body, len)` | 按目标 handle 绑定的队列投递，失败回退 `queue_core` |
| | `queue_emit(host, q, handle_key, body, len)` | 明确投到某条分流队列，失败回退 `queue_core` |
| 分流队列 | `queue_create(host, name, capacity, dll, &q)` | 建队列 + Dispatcher + 常驻线程，幂等（重名直接返回已有的） |
| | `queue_destroy(host, q)` | 停线程 → join → 释放；**在自己的分发线程上销毁自己的队列会返回 `MDPSR_ERR_QUEUE_SELF`** |
| | `queue_bind(host, handle_key, q)` | 把 handle 绑到某条队列（改的是 Map 里的 `bind_queue`） |
| | `queue_core(host)` | 取默认队列 `queue_core`（没有就返回 NULL） |
| | `queue_list(host, out, cap, &n)` | 全部分流队列快照 |
| | `dispatcher_count(host)` | 当前存活的 dispatcher 数量 = 分流线程数 |
| 清单 | `manifest_dll / manifest_count / manifest_entry / manifest_path` | 读清单（宿主解析后的快照） |
| 插件装载 | `plugin_load(host, manifest_rel, &dll)` | 全套装载，见下 |
| | `plugin_unload(host, dll)` | 全套卸载 |
| | `plugin_loaded(host, dll)` | 1 = 已加载 |
| | `plugin_keys(host, dll, out, cap, &n)` | 这个 dll 在 Map 里的全部键 |

### 10.1 `plugin_load` / `plugin_unload`

这两个是**宿主引导和内核 DLLMgr 共用的同一份实现**，插件也可以直接调用它们
（比如你想自己实现一个管理器）：

```
plugin_load(manifest_rel, &dll)
    解析清单 → LoadLibrary + module_init → 建专属池
    → 建组件申请的 queue（Queue + Dispatcher + 常驻线程）
    → 调 state/object 工厂并注册
    → 注册 handle 并绑定 state / object / 分流队列
    返回 MDPSR_OK / MDPSR_ERR_ALREADY_EXISTS / MDPSR_ERR_PLUGIN_*

plugin_unload(dll)
    失效 → 等计数归零 → 摘出队列并置停
    → 锁外 join 线程 → 析构 object/state/handle → 释放队列槽位
    → 摘表 → 整池释放 → FreeLibrary
    返回 MDPSR_OK / MDPSR_ERR_PLUGIN_BUSY(还有人在用) / MDPSR_ERR_PLUGIN_NOT_FOUND
```

`manifest_rel` 必须是**相对运行时根目录**的路径。
`plugin_load` / `plugin_unload` 内部由一把全局锁串行化——
多分发线程同时装载是安全的，但也是**串行**的。

## 11. 结构与助手速查

### 11.1 `mdpsr_state`

```c
struct mdpsr_state {
    uint64_t    name;     // Hash(条目名), 也是 Map 的键。宿主会覆盖
    uint64_t    dll;      // 所属 dll 键。宿主会覆盖
    uint32_t    kind;     // ★ 插件自定义类型标签
    uint32_t    flags;    // ★ 插件自定义标志
    size_t      size;     // payload 字节数
    void*       payload;  // 公用数据本体
    mdpsr_resource* res;  // 分配 payload 用的池
    mdpsr_state_destroy_fn destroy;  // 可选析构
};
```

| 助手 | 作用 |
| --- | --- |
| `mdpsr_state_new(res, kind, size)` | 从池里造一个 State（含 payload 分配） |
| `mdpsr_state_delete(st)` | 先跑 `st->destroy`，再释放 payload 与 st |
| `mdpsr_state_as<T>(st)` | `static_cast<T*>(st->payload)` |

### 11.2 `mdpsr_classptr`（object 的索引）

```c
typedef struct mdpsr_classptr {
    uint64_t name;      // Hash(条目名)
    uint64_t dll;
    uint32_t kind;
    uint32_t flags;
    void*    instance;  // 类实例指针
    void*    destroy;   // 可选析构 mdpsr_object_destroy_fn
    void*    itable;    // 可选接口表
} mdpsr_classptr;
```

### 11.3 `mdpsr_handle` / `mdpsr_handle_core`

```c
struct mdpsr_handle {
    uint64_t id; uint64_t dll;
    uint32_t kind;      // 0 = Handle, 1 = Handle_core
    uint32_t flags;
    mdpsr_handle_fn fn;
    char     name[MDPSR_NAME_MAX];
};
typedef struct mdpsr_handle_core {
    mdpsr_handle base;
    uint32_t     is_core;
    uint32_t     pad;
    void*        user;   // 内核私有数据
} mdpsr_handle_core;
```

### 11.4 `mdpsr_dllptr`（专属池索引）

```c
typedef struct mdpsr_dllptr {
    uint64_t dll; uint32_t flags; uint32_t pad;
    mdpsr_resource* pool;     // 该 dll 的专属池
    char name[MDPSR_PATH_MAX];
} mdpsr_dllptr;
```

### 11.5 `mdpsr_queue`（Map 的第四类条目）

```c
typedef struct mdpsr_queue {
    uint64_t name;      // Hash(队列名), 也是 Map 的键
    uint64_t dll;       // 所属 dll 键; 0 = 核心 queue_core
    uint32_t flags;
    uint32_t capacity;  // 初始环形缓冲字节数
    void*    impl;      // 宿主内部 Queue* 的不透明句柄
    char     label[MDPSR_NAME_MAX];
} mdpsr_queue;
```

* `label` 是给人看的队列名（`impl` 才是真身，别去动它）。
* 想判断"我现在在哪个队列上"，比 `cc.queue->name` 或 `cc.queue->label`。
* 默认队列的名字常量：`MDPSR_QUEUE_CORE_NAME` = `"queue_core"`。

### 11.6 通用助手一览（`abi.h` 里的 `static inline`）

| 助手 | 作用 |
| --- | --- |
| `mdpsr_hash64(s)` | 与宿主一致的哈希 |
| `mdpsr_state_new / mdpsr_state_delete / mdpsr_state_as<T>` | State 生命周期 |
| `mdpsr_path_join(out, cap, base, rel)` | 拼相对路径并消解 `.` / `..` |
| `mdpsr_read_pod<T>(data, len, out)` | 安全拷贝一段 POD，长度不够返回 `false` |
| `mdpsr_read_str(data, len, offset)` | 取 NUL 结尾字符串，越界返回 `nullptr` |
| `mdpsr_find_state(slots, count, name)` | 在 `Content::states` 里按名取 state |
| `mdpsr_dllmgr_pack(out, cap, cmd, dll, path)` | 组一条 DLLMgr 消息（内核专用） |

## 12. 硬性规则清单

写 / 改插件时对照这张表：

| # | 规则 |
| --- | --- |
| 1 | 导出 `mdpsr_abi_version` / `mdpsr_module_init`（`mdpsr_module_fini` 可选） |
| 2 | 所有导出用 `extern "C"`，**不让异常穿过 DLL 边界** |
| 3 | **Handle 必须无状态**；非 cache 的状态一律放 State |
| 4 | 条目名**全局唯一**（handle 与 object 不能同名；队列名也共用同一个键空间） |
| 5 | State 载荷**必须**从 `ctx->pool`（Pool_state）分配 |
| 6 | State 载荷里放了 C++ 对象就**必须**设 `st->destroy` |
| 7 | Object 实例从 `ctx->pool`（该 DLL 专属池）分配；析构导出名 = 工厂名 + `_destroy` |
| 8 | 别的组件要数据走 State，**不要**去摸别人的类实例 |
| 9 | 收到消息先校验长度（`mdpsr_read_pod`），**不要**越界读 |
| 10 | 路径统一用「相对运行时根目录」的 UTF-8 形式；清单内相对路径用 `mdpsr_path_join` |
| 11 | 自己起的线程与 handle 共享数据时要自己加锁（同一队列内串行，**跨队列是并发**） |
| 12 | 库内部不要保留可变全局状态（内核 DLLMgr 把字典放 State 里就是范例） |
| 13 | **队列只在 `plugin.json` 的 `queue` 段声明**，别自己 `new Queue` / 自己起 dispatcher 线程——那是宿主的活 |
| 14 | handle 想分流就在清单里给它写 `"queue": "队列名"`；省略就走 `queue_core` |
| 15 | 组件卸载时**它的队列与线程会被一起回收**，所以**不要在别的线程里长期持有 `mdpsr_queue*`**，也不要缓存 `Content::queue` |
| 16 | 需要建队列/绑定/直接投递时，用 `host->queue_create / queue_bind / queue_emit`（后门级接口），不要绕过宿主自己搞一套调度 |
| 17 | **不要在自己的分发线程上销毁自己的队列**（宿主会返回 `MDPSR_ERR_QUEUE_SELF`，因为会自 join 死锁） |

## 14. 最小可编译示例

```cpp
// my_plugin.cpp
#include <mdpsr/abi.h>

/* ---- state: 一个公用配置 ---- */
struct MyConfig { int32_t interval_ms; };
#define KIND_MYCFG 0x4D594346u   /* 'MYCF' */

MDPSR_EXPORT mdpsr_state* mdpsr_state_myconfig(const mdpsr_state_ctx* ctx) {
    if (!ctx || !ctx->pool) return nullptr;
    mdpsr_state* st = mdpsr_state_new(ctx->pool, KIND_MYCFG, sizeof(MyConfig));
    if (!st) return nullptr;
    auto* c = static_cast<MyConfig*>(st->payload);
    c->interval_ms = 500;
    return st;
}

/* ---- queue: 给自己的 handle 申请一条专属分流线程 ---- */
MDPSR_EXPORT int mdpsr_queue_my(const mdpsr_queue_ctx* ctx, mdpsr_queue_desc* out) {
    if (!ctx || !out) return MDPSR_ERR_NULLPTR;
    out->struct_size = static_cast<uint32_t>(sizeof(mdpsr_queue_desc));
    out->flags       = 0;
    out->capacity    = 4096;
    return MDPSR_OK;
}

/* ---- handle: 无状态命令入口 ---- */
MDPSR_EXPORT int mdpsr_handle_my(const uint8_t* msgData, size_t msgLen,
                                 const uint8_t* ctxData, size_t ctxLen) {
    mdpsr_content cc{};
    if (!mdpsr_read_pod(ctxData, ctxLen, &cc)) return MDPSR_ERR_NULLPTR;

    mdpsr_ctrl_msg m{};
    if (!mdpsr_read_pod(msgData, msgLen, &m)) return MDPSR_ERR_BAD_MESSAGE;

    auto* cfg = mdpsr_state_as<MyConfig>(
        mdpsr_find_state(cc.states, cc.state_count, "My.Config"));

    if (cc.host && cc.host->log) {
        char line[160];
        std::snprintf(line, sizeof(line), "[My] cmd=%d interval=%d queue=%s",
                      m.cmd, cfg ? cfg->interval_ms : -1,
                      cc.queue ? cc.queue->label : "(无)");
        cc.host->log(cc.host->host, 0, line);
    }
    return MDPSR_OK;
}

/* ---- 模块导出 ---- */
MDPSR_EXPORT uint32_t mdpsr_abi_version(void) { return MDPSR_ABI_VERSION; }
MDPSR_EXPORT int mdpsr_module_init(const mdpsr_host* host, uint64_t dll) {
    if (!host || host->abi_version != MDPSR_ABI_VERSION) return MDPSR_ERR_PLUGIN_ABI;
    return MDPSR_OK;
}
MDPSR_EXPORT void mdpsr_module_fini(uint64_t) {}
```

配套 `plugin.json`：

```json

  "queue": {
    "My.Thread": { "symbol": "mdpsr_queue_my", "capacity": 4096 }
  },
  "handle": {
    "My.Cmd": {
      "symbol": "mdpsr_handle_my",
      "type": "handle",
      "state": "My.Config",
      "queue": "My.Thread"
    }
  },
  "state": {
    "My.Config": { "symbol": "mdpsr_state_myconfig" }
  }
}
```
