一、状态机架构

Pool_msg
synchronized_pool_resource，负责消息字节流的内存分配

Pool_map
synchronized_pool_resource，负责 Map 内部节点和引用计数指针的分配

Pool_dll
unordered_map<uint64_t, unique_ptr<synchronized_pool_resource>>
以 DLL 的哈希值为键，每个 DLL 一个独立池，DLL 卸载时整池释放

Pool_state
全局公共可变长资源，unsynchronized_pool_resource
负责跨 DLL 共享的 State 和可变长 cache

Queue
类对象，字节流模式，可扩展环形字节缓冲队列

消息在队列中的布局（序列化后连续字节）：
uint32_t _length 本条消息的总字节长度
uint64_t _handle 目标 Handle 的哈希值
uint8_t _buffer[] 附带信息（实际长度由 _length 决定）

说明：Message 不以对象形式入队，而是序列化为连续字节。
队首先写入 _length 和 _handle，再写入 _buffer。
当队列中可读字节数 >= _length 时，认为一条完整消息就绪。

Dispatcher
类对象，单线程，被动响应式
当 Queue 中积累出一条完整 Message 后，取出 _handle，查表分发

Handle 可获得：Content
Handle_core 可获得：CoreContent

struct Content {
State* state;
Classptr* classptr;
}

struct CoreContent {
State* state;
Classptr* classptr;
Handle* handle;
Handle_core* handle_core;
Classptr* classptr_all;
DLLptr* dllptr;
}

Map
类对象，内含多张可变长字典，键为 uint64_t，值为 Countptr
键由名称哈希而来，作为全局唯一标识

struct Countptr {
void* ptr; 对象指针
int r_count; 读计数，读取时 +1，读完 -1
int w_count; 写计数，写入时 +1，写完 -1
bool valid; 有效性，false 时视为不存在
}

类型说明
Handle 一般 Handle，入口参数中只暴露 Content
Handle_core 内核级 Handle，入口参数中暴露 CoreContent
State 公用状态，也作为可变长 cache 使用
Classptr 所有 DLL 类的指针索引
DLLptr 所有 DLL 的 pmr::unsynchronized_pool_resource 索引

三、DLL 内核

内核只向 Map 注册一个特殊 Handle：
Hash("DllMgr") -> Handle_core

内核收到的 Message 的 buffer 强类型转化为：
struct DllCmd {
int cmd;
uint64_t dll_name;
}

cmd = 0 初始化
在 Pool_state 中创建一个可变字典 Dll_dict：
key = uint64_t(dll_name)
value = vector<uint64_t>，存储该 DLL 在 Map 中占用的
所有 State 和 DLLptr 的键
用于统一记录和释放

cmd = 1 加载 DLL
读取该 DLL 对应的 json 配置
对 "state" 字段：在 Pool_state 中调用对应 DLL 函数，把返回的
State 托管到池管理，并把键登记到 Dll_dict
对 "object" 字段：在 Pool_dll 中为该 DLL 创建专属池，把 DLL
类 new 到该池中，并把键登记到 Dll_dict

cmd = 2 卸载 DLL
通过 Dll_dict 查询 dll_name，取出该 DLL 的所有资源键
启动等待：轮询这些资源的 r_count 和 w_count，直到全部为 0
先统一把 valid 置为 false（阻止新的读取）
再按顺序释放 State 和 Object，最后整池释放 Pool_dll 中该 DLL 的池

四、添加插件

插件配置 json 结构：

{
"dll_path": [ 相对本 json 位置的 dll 路径列表 ],
"handle": [ 该 dll 内导出的 Handle 名称，标明类型 Handle 或 Handle_core ],
"object": { 对象名称: 该对象对应的 dll 导出函数名称 },
"state": { state 名称: 该 state 对应的 dll 导出函数名称 }
}

约定：

所有导出函数必须使用 C 风格链接（extern "C"）

"handle" 导出的函数签名必须为：
int func(const uint8_t* msgData, size_t msgLen,
const uint8_t* ctxData, size_t ctxLen);
且必须为无状态函数（不依赖、不修改任何全局状态）

上下文 ctxData 由 Dispatcher 按 Handle 类型构造：
Handle -> Content
Handle_core -> CoreContent
插件自行按约定解析上下文

"object" 导出的函数只返回一个类指针

"state" 导出的函数返回需要的公用对象指针
